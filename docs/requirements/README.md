# Требования Adrobot

[ТЗ v0.3.1](Adrobot_TZ_v0.3.1.md) определяет поведение, границы продукта и критерии
приёмки. YAML-файлы помогают находить требования и прослеживать связи. В случае
расхождения сверяйся с ТЗ и исправляй производную запись.

| Файл | Назначение |
|---|---|
| [00_manifest.yaml](00_manifest.yaml) | Действующий источник, SHA-256, происхождение и индекс разделов |
| [01_contract.yaml](01_contract.yaml) | Правила с ID, определения и внутренние маршруты |
| [02_acceptance.yaml](02_acceptance.yaml) | 37 критериев приёмки, DoD и примеры расчётов |
| [03_api_discovery.yaml](03_api_discovery.yaml) | Вопросы OPEN и работы, которые от них зависят |
| [04_tasks.yaml](04_tasks.yaml) | План задач, зависимости и ссылки на правила и критерии |

Для конкретной задачи открой её запись в плане, используй связанные rule_refs и
acceptance_refs и сверяйся с указанными source_sections. Правила SCP относятся
ко всему проекту. Утверждённые решения DESIGN и стандарты ENG действуют в
пределах ТЗ. Приёмка определяется исходными критериями и DoD. Один критерий
может требовать нескольких проверок, например расчёта и последующего Push.

Факты об интеграции и её открытые вопросы ведутся в [заметках Keitaro](../keitaro-api-notes.md).
Отмечай отдельно сведения документации, фактически проверенное чтение и
подтверждённую мутацию с readback. Если API-факт меняет принятое решение,
зафиксируй наблюдение и разберись с изменением по правилам проекта. Работу,
которая не зависит от открытого вопроса, можно продолжать.

Порядок локальной разработки и внешнего ревью описан в [AGENTS.md](../../AGENTS.md).
Операционный статус задач хранится в локальной SQLite authority.

## Проверка целостности

Из корня репозитория с существующим проектным окружением:

    uv run --locked python checks/validate_pack.py

Для полной проверки нужен оригинальный исторический архив
`.ai-work/reference/Adrobot_requirements_review_v0.2.zip`. Его SHA-256 указан в манифесте.
Архив хранит исходные материалы и прежнее ревью. Вложенные старые ТЗ
используются только для проверки происхождения требований.

Валидатор сверяет хеши, индекс разделов, ссылки, зависимости задач и дословность
AC и DoD. Результат описывает целостность документов. Поведение приложения и
интеграция принимаются по своим проверкам.
